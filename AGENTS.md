# Working in Ghost Algolia

This repository contains the Ghost-to-Algolia CLI, Netlify Functions, and their shared packages. Read [README.md](README.md) for the user-facing overview.

## Revival and Ghost 6 compatibility

- Maintenance is resuming because these tools are still in active use.
- The CLI uses the Ghost 6 Content API. Without `--limit`, it requests 100 posts per page, follows `meta.pagination.next`, and waits 100ms between pages until `next` is `null`.
- `--limit` accepts only integers from 1 to 100 and makes one request. `--page` requires `--limit`; together they select one page rather than enabling automatic pagination.
- Preserve the existing Ghost Content API, Algolia record, CLI, and webhook contracts unless the task explicitly changes them.

## Verification

- Run `yarn test` from the repository root for the root and package test suites; package `posttest` scripts also run ESLint.
- Run `yarn lint` for a lint-only monorepo check.
- Use `yarn workspace <package-name> test` for a focused package check, then run the full suite before handoff.
- For Netlify function changes, copy `packages/algolia-netlify/.env.example` to `.env`, use development credentials, and run `yarn dev` from that package directory.
- Run `yarn typecheck` for the strict TypeScript function and test configurations.

## Boundaries

- Treat `.env` files and CLI configuration files as secret-bearing local state. Commit only the provided examples, and use non-production Ghost and Algolia credentials for manual checks.
- Netlify handlers use `.mts` default exports with the native `Request`/`Response` interface. Keep the `post-published` and `post-unpublished` basenames and do not add `config.path`; the basenames preserve the live `/.netlify/functions/...` URLs.
- `packages/algolia-netlify/.netlify/` is generated by `yarn build`; edit sources under `functions/` rather than generated output. The build must publish only `public/`, never package or function source files.
- All four workspaces are public npm packages. Changes to exports, CLI flags, record shapes, required Algolia settings, or webhook behavior need compatibility review and release notes. `yarn ship` publishes packages and is a maintainer-only operation.
- Tests invoke the native Netlify request seam and real fragmenter/indexer code while replacing only the external Algolia requester. Keep automated verification deterministic and offline; use manual development environments for end-to-end network checks.
